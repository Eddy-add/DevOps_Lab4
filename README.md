## 1. Цель работы

Изучить архитектуру и основные принципы работы системы управления конфигурациями Ansible и автоматизировать развёртывание веб-сервера Nginx на удалённом управляемом узле:
1. Освоить организацию сетевого взаимодействия между управляющим (`Control-node`) и управляемым (`Managed-node`) узлами в общей виртуальной сети NAT (`NatNetwork`).
2. Настроить безопасное безагентное (`agentless`) взаимодействие по протоколу SSH с использованием криптографических ключей и беспарольного повышения привилегий (`sudo`).
3. Изучить структуру инвентарных файлов (`inventory.ini`), декларативных сценариев (`playbook.yml`), режим проверки (`--check`) и принцип идемпотентности при выполнении задач.
4. Автоматизировать установку веб-сервера Nginx (`ansible.builtin.apt`) и доставку пользовательской индексной страницы (`ansible.builtin.copy`) с последующей проверкой доступности сервиса по протоколу HTTP.

## 2. Схема стенда и используемые инструменты

* **Control-node (Управляющий узел):** ВМ-1 на базе Ubuntu 26.10 (`damir@Damir`, статический IP-адрес `10.0.2.15`, установлен пакет `ansible` версии `13.4.0` / `ansible-playbook [core 2.22.0b2]`, рабочая директория проекта `~/lab-ansible`).
* **Managed-node (Управляемый узел):** ВМ-2 на базе Ubuntu 26.10 (статический IP-адрес `10.0.2.16`, Python `3.14.8`, запущен `openssh-server`, настроен сервисный пользователь `runner` с правом беспарольного `sudo` и входом по SSH-ключу).
* **Сетевая инфраструктура:** Общая сеть NAT (`NatNetwork`, подсеть `10.0.2.0/24`) в Oracle VM VirtualBox с настроенными правилами проброса портов (`Port Forwarding`):
  * `127.0.0.1:2222` $\rightarrow$ `10.0.2.15:22` (SSH-управление ВМ-1);
  * `127.0.0.1:2223` $\rightarrow$ `10.0.2.16:22` (SSH-управление ВМ-2);
  * `127.0.0.1:80` $\rightarrow$ `10.0.2.16:80` (HTTP-доступ к веб-серверу Nginx на ВМ-2 с хостовой ОС).
* **Клиентские инструменты (Хост Windows):** SSH-клиент **Termius** для одновременного удалённого управления обоими серверами и веб-браузер для проверки работы развёрнутого веб-сервера.

## 3. Ход выполнения работы

### 3.1. Подготовка виртуальных машин и сетевого окружения в VirtualBox

1. На первой виртуальной машине (ВМ-1) в планировщике задач `crontab -e` отключён регулярный запуск скрипта `weather.sh` из предыдущей лабораторной работы.
2. Выполнено полное клонирование первой ВМ с обязательной политикой **«Сгенерировать новые MAC-адреса всех сетевых адаптеров»** во избежание конфликтов на канальном уровне.
3. В менеджере VirtualBox (**Инструменты $\rightarrow$ Сеть $\rightarrow$ Сети NAT**) создана общая сеть `NatNetwork` с префиксом IPv4 `10.0.2.0/24` и настроены правила проброса портов для SSH (`2222`, `2223`) и HTTP (`80`), после чего сетевые адаптеры обеих машин подключены к `NatNetwork`:

![Настройка общей сети NatNetwork в Oracle VM VirtualBox Менеджер](<Снимок экрана 2026-11-26 231348.png>)

4. Для исключения смены динамических DHCP-адресов при перезагрузках на обеих ВМ отредактирован конфигурационный файл Netplan (`/etc/netplan/50-cloud-init.yaml`) с закреплением статических адресов `10.0.2.15/24` (ВМ-1) и `10.0.2.16/24` (ВМ-2):

```yaml
network:
  version: 2
  renderer: NetworkManager
  ethernets:
    enp0s3:
      dhcp4: false
      addresses: [10.0.2.15/24]
      routes: [{ to: default, via: 10.0.2.1 }]
      nameservers:
        addresses: [1.1.1.1]
```

Применение настроек выполнено командой `sudo netplan apply`, а корректность назначения адресов проверена с помощью `ip addr show enp0s3`.

### 3.2. Настройка пользователя `runner`, SSH-доступа и установка Ansible

Поскольку Ansible выполняет конфигурацию удалённых узлов по протоколу SSH без установки дополнительных агентов, на целевой машине (ВМ-2) подготовлена учётная запись `runner` с правами администратора без запроса пароля:

1. На **ВМ-2 (`10.0.2.16`)** создан пользователь `runner`, добавлен в группу `sudo`, а в `/etc/sudoers.d/runner` добавлено правило `NOPASSWD`:

```bash
sudo useradd -m runner
sudo passwd runner
sudo usermod -a -G sudo runner
echo "runner ALL=(ALL) NOPASSWD: ALL" | sudo tee /etc/sudoers.d/runner
sudo chmod 0440 /etc/sudoers.d/runner
```

2. С **ВМ-1 (`10.0.2.15`)** публичный SSH-ключ скопирован на ВМ-2 в профиль `runner` командой `ssh-copy-id runner@10.0.2.16`.
3. После подключения к обоим узлам через SSH-клиент **Termius** на ВМ-1 выполнена проверка беспарольного входа и повышения привилегий (`ssh runner@10.0.2.16 "sudo whoami"`), а также установка пакета `ansible` и проверка его версии:

```bash
ssh runner@10.0.2.16 "sudo whoami"
sudo apt update && sudo apt install -y ansible
ansible-playbook --version
```

### 3.3. Создание файлов проекта (Inventory, Index и Playbook)

На управляющем узле **ВМ-1 (`10.0.2.15`)** в домашнем каталоге создана рабочая директория `~/lab-ansible` и подготовлены три файла конфигурации:

1. **Инвентарный файл (`inventory.ini`)** — описывает группу управляемых хостов `[webservers]` и IP-адрес целевого сервера:

```ini
[webservers]
10.0.2.16
```

2. **Шаблон индексной веб-страницы (`index.html`)** — локальный исходный файл на управляющем узле, который копируется в корневой каталог веб-сервера:

```html
<HTML>
<BODY>
<h1>Hello from Ansible playbook!</h1>
</BODY>
</HTML>
```

3. **Сценарий развёртывания (`playbook.yml`)** — декларативный YAML-файл, описывающий последовательность задач:
   * `Install nginx` — обновление кеша пакетов и установка актуальной версии пакета `nginx` через модуль `ansible.builtin.apt`;
   * `Copy index` — копирование локального файла `./index.html` в `/var/www/html/index.nginx-debian.html` с установкой владельца `root:root` и прав доступа `0666` через модуль `ansible.builtin.copy`:

```yaml
---
- name: Deploy nginx
  hosts: webservers
  remote_user: runner
  become: yes
  become_method: sudo
  tasks:
    - name: Install nginx
      ansible.builtin.apt:
        name: nginx
        state: latest
        update_cache: yes

    - name: Copy index
      ansible.builtin.copy:
        src: ./index.html
        dest: /var/www/html/index.nginx-debian.html
        owner: root
        group: root
        mode: '0666'
```
